## Lessons to carry forward

1. **Session-start step 3 is non-optional.** D5 skipped the
   state-file pull from Drive at session-start; surfaced only at
   EOD when state-file writes failed. Recovered with a post-hoc
   pull. SYNC_PROTOCOL Revision 5 (proposed) addresses this.

2. **The D4 journal's "computed live by verifier" diagnosis was
   wrong.** The BCF section in verify_foundation.py
   (`check_section_11_boundary`) is a static CSV-vs-JSON comparison.
   Catching this via grep-first-patch-after produced a ~5x scope
   reduction on the Q-007 fix vs what the preflight estimated.

3. **Schema-inspect before joining files.** Four script-patch
   iterations on f2_partial_r2.py were avoidable (paths, column
   names, prefix strip, dtype coercion). When writing a script that
   joins files I haven't read directly, inspect schemas first —
   write-then-debug is more expensive.

4. **The "11 cells" framing was carried wrong** from earlier
   planning. bcf_pairs.csv has 12 NNLS cells (ByteDance h10 is in,
   delta_pp +6.97; D2 incidental finding). Verify cell counts
   directly from canonical inputs, not from prior notes.

5. **F2 null is structural, not methodological.** R²_reduced = 0.903
   means the test was set up against a near-impossible threshold on
   this corpus. The honest framing is "ACF@24h + horizon saturate
   the cell-level predictability axis; PE adds nothing on cloud
   traces." This is a defensible chapter contribution, not a
   failed experiment.
