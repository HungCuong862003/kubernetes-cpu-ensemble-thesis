## Revision 4 (2026-05-27)

**State-file edits use Local-first canonical workflow, separate from
compute-artefact workflow.**

Distinction:

- **State files** (THESIS_STATE.md, DECISIONS.md, ERRATA.md, handoffs/*.md,
  SYNC_PROTOCOL.md itself, journal/*.md): human-authored. Editor quality
  matters (notepad/VS Code on Windows). Edit on Local first.
- **Compute artefacts** (phase_f/scripts/*.py, phase_f/data/*.csv,
  phase_f/scripts/*.log): machine-generated. Where they run is where
  they're canonical. Edit/produce on Vast.ai.

### Local-first state-file workflow (state files only)

1. **Local Windows: edit the .md file** in notepad or editor of choice.
   Save. Verify with `Get-Content .\phase_f\<file>.md -TotalCount 5`.

2. **Local → Vast.ai: upload** the edited file to Vast.ai workspace.
   Two options:
   - Via Drive (preferred — single intermediate): `rclone copy
     .\phase_f\<file>.md gdrive:kubernetes-cpu-ensemble-thesis/phase_f/`,
     then on Vast.ai SSH: `rclone copy gdrive:.../phase_f/<file>.md ./phase_f/`
     (or `./` for state files that live at workspace root: THESIS_STATE.md,
     DECISIONS.md, ERRATA.md, handoffs/*).
   - Direct (no Vast.ai boot needed if next session-start picks it up):
     skip step 2 entirely. Vast.ai pulls from Drive at next session-start
     per the existing "Drive → Vast.ai" session-start flow.

3. **Local → Drive: push directly** (done as part of step 2 option a, or
   as a separate step if option b chosen).
```powershell
   rclone copy .\phase_f\<file>.md gdrive:kubernetes-cpu-ensemble-thesis/phase_f/
```

4. **Verify md5 match** across whichever layers are populated:
```powershell
   # Local
   $localMd5 = (Get-FileHash .\phase_f\<file>.md -Algorithm MD5).Hash.ToLower()
   # Drive
   $driveMd5 = (rclone hashsum md5 gdrive:.../phase_f/<file>.md).Split(' ')[0]
   # Vast.ai (if uploaded — over SSH)
   #   md5sum ./phase_f/<file>.md  (returns md5 + filename)
```
   All populated layers must match the same hash.

5. **Git commit + push from Local** (always — git lives only on Local):
```powershell
   git add phase_f/<file>.md
   git diff --cached --name-only
   @"..."@ | Out-File -Encoding UTF8 -NoNewline -FilePath .\_commit_msg.txt
   git commit -F .\_commit_msg.txt
   Remove-Item .\_commit_msg.txt
   git push origin feature/live-demo
```
   Verify `git rev-parse HEAD == origin/feature/live-demo`.

### Compute-artefact workflow (unchanged from earlier revisions)

Standard EOD flow from §"Standard EOD flow (Vast.ai work on the day)"
applies: Vast.ai → Drive → Local → git. No change.

### Why the split

Earlier revisions assumed one-directional canonical-source-of-truth
per day (either Vast.ai-first for compute days, or Local-first for
chat-only days). D4 + D5 showed that state files and compute
artefacts have different natural homes within a single day:
- D4 wrote scripts + ran them on Vast.ai (compute), then edited state
  files on Local (after the day's compute work concluded).
- D5 similar — F2 regression on Vast.ai, ERRATA-012 + handoff on Local.

Forcing both through one canonical source ends up either
(a) editing .md on Vast.ai via nano (worse editor experience, CRLF
risk from heredocs), or (b) pulling compute artefacts to Local
unnecessarily before commit.

The split keeps the editor where the editor is best, and the compute
where the compute runs.

### Rclone single-file gotcha (still applies)

`rclone copy gdrive:path/file.md ./` on Vast.ai SSH **silently no-ops**
for single-file source paths. Workaround: pull the whole directory,
or use `rclone copyto` for true file-to-file copy. This applies to
session-start state-file pulls (Drive → Vast.ai) and EOD pushes
both ways. See D4 close log for the diagnostic trail.

### Md5 verification on single files (still applies)

`rclone check` fails with "is a file not a directory" when applied to
single-file targets. Use `rclone hashsum md5` on both sides and
compare strings instead. Directory `rclone check` works as documented.
